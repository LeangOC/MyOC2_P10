## Règles métier couvertes

Les principales règles métier sont directement couvertes par les User Stories :

* **US-08** : la date de retour doit être postérieure d'au moins 2 heures à la date de départ.
* **US-11** : les véhicules utilisent la classification ACRISS.
* **US-18** : une réservation peut être modifiée jusqu'à 48 heures avant son début.
* **US-19 / US-20** : les règles de remboursement dépendent du délai avant le départ.
* **US-15** : le paiement est externalisé via Stripe et aucune donnée de carte bancaire ne transite par les serveurs YCYW.
* **US-26** : le tchat utilise WebSocket/STOMP, conserve l'historique et nécessite une authentification JWT.
* **US-27 / US-28** : les exigences d'accessibilité couvrent notamment WCAG 2.1 AA, RGAA 4.1, navigation clavier et lecteurs d'écran.
* **US-30** : la sécurité impose notamment Argon2id, HTTPS/TLS 1.3, gestion sécurisée des secrets et protection contre les vulnérabilités OWASP.
* **US-31** : les objectifs comprennent notamment un p95 inférieur à 500 ms et une capacité cible d'au moins 500 requêtes/seconde.
* **US-29** : l'internationalisation prévoit au minimum FR, EN, DE, ES et IT, avec gestion des fuseaux horaires et formats locaux.
* **US-33** : l'éco-conception prévoit notamment un score Lighthouse Performance ≥ 85, l'optimisation des assets et la pagination serveur.

## Definition of Done

Une User Story est considérée comme terminée lorsque :

* [ ] Les critères d'acceptation sont respectés.
* [ ] Le parcours nominal fonctionne.
* [ ] Les cas d'erreur sont gérés.
* [ ] Les tests nécessaires sont réalisés.
* [ ] Les contrôles de sécurité applicables sont réalisés.
* [ ] Les exigences d'accessibilité applicables sont vérifiées.
* [ ] La documentation nécessaire est mise à jour.
* [ ] Le code est intégré dans le dépôt.
* [ ] Les contrôles qualité sont satisfaisants.
* [ ] Aucune régression connue n'est introduite.
